# Council 1.5: what was added and what is proven

Version 1.0 runs on the real box through Ollama. Version 1.5 adds the pieces below. The spec for each is in
`docs/ARCHITECTURE.md` (sections named in brackets). The routes and events are in `docs/API.md`.

## Decisions that shape 1.5

1. **llama.cpp serves the models.** One `llama-server` process per model, loading the GGUF file that Ollama
   downloaded. Ollama is only the downloader. The Ollama driver is kept as a fallback, chosen by `[host] driver`
   (6.1).
2. **Per-project adaptation: steering vectors only.** A llama.cpp control vector, built from contrast prompts
   and the model's own activations (27.9). Shown to work in one experiment (`tools/box/steer_test.py`); the library
   (`council/steer/`) is included and is not used by a default run.
3. **The council has 11 models and a run seats 2 to 6.** The user picks the size (`options.k`). A memory plan may
   seat fewer (29).

## Proven on the box

- **The steering experiment**, `tools/box/steer_test.py`, on Granite 4.1 8B. Three rules (French, terse, camelCase
  names), layers 14 to 26. Steering works and is specific; a random vector of the same size does nothing useful. The
  usable strength range is narrow, so the vector must be scaled to a small fraction of the hidden state and the
  strength searched with a sanity check. Reversing with a negative strength works only for small vectors.
- Version 1.0 itself (the Ollama path), as before this wave.

## Proven in mock mode only

Everything else in 1.5. That means the code runs, the tests pass, and the events and routes have the right shape. It
does not mean the numbers are right on the real machine.

- **llama.cpp driver on the box.** Not yet run for a full council. Port use, start-up time, health and the child
  processes under six models at once are unseen.
- **Lie detector.** No probe has been trained on a real model, so no real AUROC is known. Whether any probe passes the
  gate is open. The `actdump` tool exists and was used by the steering experiment, but the probe training on it has not
  been run.
- **Steering service in the pipeline.** The method is box-proven; the service that trains it after a correction, the
  strength search through the real gateway, and `steer.applied` on a real run are mock-proven (a fake steering driver
  in tests). Only Granite 4.1 8B has seen a vector. The default `target_fraction = 0.06` and strengths
  `0.5 .. 2.0` are starting values.
- **Memory plan.** The inputs (121.6 GiB total, about 16.5 GiB per 12 GiB model at 16384 tokens) were measured earlier.
  The plan itself, per-model context and role sharing have not run against the real box.
- **Speculative decoding.** Pairs are proposals. `verified` and `speedup` are empty until `tools/box/specdec_bench.py`
  has measured them.
- **Council sizes 2 to 6.** Run in mock mode (answer at 2, 3, 4 and 6 seats, a 2-seat build with a review pass). No
  real run at each size yet.
- **Comparison with solo models** needs the solo results file from the benchmarking laptop; the loader accepts several
  shapes and is only tested on made-up files.

## Dropped

LoRA adapters: dropped, never implemented.

## Known open points

- Fix pass items left open: a worker that writes a test file with no test methods passes its task (needs a user
  decision); parallel tasks in one staged tree each run the whole test suite; a `settles` text in the evidence view.
- `probe/gate.py` and `probe/trainer.py` use different baseline margins (0.03 and 0.1). They should be equal.
- Mock `MockDriver` cannot steer, so a mock run never emits `steer.applied`.
- `ui/src/types.ts` and `api.ts` do not yet know the 1.5 routes and events (API.md, section 11).

## Next: the box run

In this order: start the `llamacpp` driver with one model and then six; run the same question at 2, 4 and 6 seats and
compare their `memory.planned` and answers; train one probe on one model and read its card; train one steering vector
through a real correction and check `steer.applied`; run `specdec_bench.py`. Each step moves one line of the section
above from "mock only" to "proven on the box". Do the install and supply-chain check from the global policy before
installing or fetching anything on the way.
